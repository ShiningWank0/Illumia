# 05. 漫画スタック

手元にある漫画のページ画像群を「1 つの作品」としてまとめ、正しい順番で読めるようにする機能。
アルバム機能の代替であり、Illumia 独自の中核機能。

## 概念モデル

```
manga_stack (作品)
  └ chapter (話)  1..n        -- chapter_no で順序
      └ page     1..n        -- page_no で章内順序、asset を参照
```

- 1 つの asset は**同一スタック内に 1 回だけ** (PK: stack_id, asset_id)。
  別スタックへの重複所属は可。
- 「同じ絵のページが作品内で 2 回必要」なケースは、重複アップロード機構
  (→ docs/11) で保存された別 asset を追加することで実現する。

## 操作仕様

### 作成
- タイムライン/検索結果で画像を複数選択 → 「漫画スタックを作成」。
- 初期状態: 第 1 話のみ、選択順 (または taken_at 順) でページが並ぶ。

### 並べ替え・話区切り (編集画面)
- ページはドラッグ&ドロップで自由に並べ替え。
- 任意のページ間に「話の区切り」を挿入 / 削除できる。区切りを削除すると前の話に統合。
- 話にはタイトルを付けられる (省略時は「第 N 話」表示)。
- 保存は `PUT /api/stacks/{id}/structure` で**章構成+全ページ順の一括置換**
  (差分 PATCH の順序整合バグを避ける。ページ数は高々数百なので一括で十分軽い)。
  リクエスト例:

```json
{
  "chapters": [
    {"title": "第1話", "pages": ["asset-a", "asset-b"]},
    {"title": null,    "pages": ["asset-c"]}
  ]
}
```

サーバーはトランザクション内で chapter_no / page_no を振り直す。

### リーダー
- スタック詳細 → 話一覧 → リーダー起動。
- 縦スクロール / 横めくり (右→左・左→右) を設定で切替。話をまたいで連続読み可。
- trashed 状態のページはプレースホルダ表示 (「削除された画像」) にし、順序は保つ。

## show_in_timeline フラグ (要件の核心)

- スタックにページを追加した時点で `show_in_timeline = 0` (既定)。
  → その画像はタイムライン・通常検索結果のイラスト一覧から消える。
- ユーザーが GUI (ページの詳細設定) でフラグを ON (`1`) にすると、
  スタック未所属の場合と同様にタイムラインへ再表示される。
- **フラグの ON/OFF はスタック所属・章・ページ順に一切影響しない** (要件で明示)。
  OFF に戻してもスタックから外れない。スタックから外す操作は別 (`DELETE .../pages/{asset_id}`)。
- 複数スタックに所属する asset は、**全ての所属で ON のときだけ**タイムラインに出る
  (1 つでも「隠す」指定があれば隠す)。
- フラグ変更時は `assets.visible_in_timeline` の非正規化列を同一トランザクションで
  更新する (→ docs/02)。

## スタック解散・ページ削除

- スタック解散 (`DELETE /api/stacks/{id}`): stack_pages / chapters を削除。
  **asset 自体は削除しない**。所属が消えるため対象画像はタイムラインに再出現する。
- ページをスタックから外す: 同上 (その asset のみ)。
- asset 側をユーザーが削除 (→ trash) する場合: 所属スタックがあれば確認ダイアログを出す。
  trash 中もページ行は保持 (リーダーはプレースホルダ)。復元すれば元通り。
  パージはスタック参照がある限り実行されない — 完全削除したい場合は
  「スタックから外して削除」を選ばせる (→ docs/11 不変条件 1)。

## Vault との関係 (→ docs/06)

- スタック丸ごと vault へ移動可 (全ページ asset + スタック構造を vault.db へ移す)。
- vault 内の画像から新規スタック作成可。
- スタックの一部だけ vault に入れる操作は**提供しない** (混在は複雑すぎる)。
  ページ単体を vault に入れたい場合は先にスタックから外す。

## 重複ビューからの追加 (→ docs/11)

- 重複ビューの asset (`lifecycle='duplicate'`) を `POST /api/stacks/{id}/pages` で
  追加できる。追加のトランザクション内で `lifecycle='active'`, `purge_after=NULL` に
  昇格させ、自動削除対象から永久に外す。
