# 10. 将来的な機能追加プラン

v1 (M1〜M6) 完了後に着手する機能。**全ての検索系機能は日本語クエリを第一級で
サポートする**ことを共通要件とする (v1 の FTS trigram と同様 → docs/03)。

## OCR 検索

- 目的: イラスト・漫画ページ内の文字 (セリフ・タイトル等) で検索できるようにする。
- モデル候補: **manga-ocr** (日本語ネイティブ、漫画のフキダシに強い)。
  サイドカーに `POST /ml/v1/ocr` を追加 (→ docs/07 で namespace 予約済み)。
- 設計: ingest 後の低優先度ジョブで全文抽出 → `ocr_texts(asset_id, text, bbox)` に保存し
  FTS5 (trigram) でインデックス。vault 分は vault.db 側のみ (→ docs/06 のログ抑制準拠)。
- 縦書き・ルビの正規化 (ルビ除去・NFKC) を行ってからインデックスする。

## スマートサーチ (自然文検索)

- 目的: 「制服の銀髪の女の子」「海辺 夕焼け」のような日本語自然文で検索。
- モデル選定基準 (ACR と同じ思想):
  1. **日本語クエリをネイティブに扱える** (翻訳挟みは精度・レイテンシで不利)
  2. ONNX エクスポート可能で onnxruntime CPU で実用レイテンシ
  3. 2 次元イラストドメインでの検索品質 (実データでベンチしてから採用)
- 候補: 多言語 SigLIP 系 / Jina CLIP v2 等の多言語画像テキスト埋め込みモデル。
  選定時にベンチ結果を docs に追記する。
- 設計: 画像側埋め込みは ingest ジョブで事前計算し DB へ (BLOB)。クエリ側は
  `POST /ml/v1/text_embed`。近傍検索は当面総当たり (数万件 × CPU で十分)、
  遅くなったら sqlite-vec を導入。
- ACR の属性タガー (WD Tagger v3) との関係: スマートサーチとタグ検索は独立の軸として
  両方提供する。

## 属性タグ検索 (WD Tagger v3)

- ACR の attributes (髪色・服装・表情スロット) を検索条件にする。
- タグは英語 (danbooru 系) なので、**日本語ユーザー名称**を付けられるようにする
  (ACR スキーマの `attr_names(slot, tag, user_name)` を Illumia DB に取り込む)。
  UI からタグへ日本語別名を登録 → FTS に別名も入れて日本語検索を効かせる。

## ML の Rust (ort) 移行

- docs/07 の RPC 契約を境界として、サイドカーを Rust 実装 (ort クレート) に置き換える。
- 移行条件: ACR のモデルバンドル (前処理パラメータ・閾値を manifest に同梱) が安定し、
  Python 版との出力一致テスト (許容誤差付き) を CI 化できること。
- 移行後は all-in-one 版から Python 同梱が消え、配布サイズ・起動時間が大幅に改善する。

## gpui 再評価

- egui からの乗り換え候補。条件: gpui の Windows サポートが安定し、Zed 外での
  利用実績・ドキュメントが揃うこと。サービス層 trait (→ docs/01) に UI を依存させて
  いるため、UI 層のみの差し替えで移行可能な構造を保つ。

## Android ネイティブ機能の拡張 (M5 の縮退分)

M5 (apps/android, Tauri 2) では以下を**縮退実装**した。将来タスクとして本格対応する。

- **自動アップロードのバックグラウンド常駐**: v1 は「アプリ起動中のフォアグラウンド同期」
  (起動時 + 手動トリガ) に限定した。将来は WorkManager の定期ジョブ + MediaStore 差分
  クエリを Tauri プラグインとして実装し、Wi-Fi のみ / 充電中のみ・指数バックオフに対応する
  (→ docs/08)。送信済み台帳も localStorage からローカル SQLite へ移す。
- **秘密の OS セキュアストレージ保存**: device token / vault パスワードは、汎用 Keystore
  プラグインが無いため v1 はプロセスメモリ内保持 (再起動で失効 → 再ログイン / 再アンロック)。
  将来は Android Keystore に「ラップ済み MK」/ device token を保存する専用プラグインを作り、
  生体認証成功時のみ復号する (→ docs/06 / docs/08)。
- **Wi-Fi SSID 紐付け**: local URL を特定 SSID にのみ試す最適化。現状 SSID 取得プラグインが
  無いため、UI と設定スキーマ (ssid フィールド) だけ用意し、判定は到達性プローブ
  (local→external, 各 2 秒) で代替している (→ docs/08)。SSID 自動取得プラグイン導入後に
  「指定 SSID 接続時のみ local を試す」を有効化する (位置情報権限の説明が必要)。
- **共有インテント (「Illumia へ送る」)**: 下記「その他の候補」にも記載。

## その他の候補 (優先度低)

- AVIF 入力。libdav1d 等の decoder、全 build target、fuzz/資源上限を確認してから明示的に追加
- Android 共有インテント (「Illumia へ送る」でアップロード)
- PWA 化 (iPhone/iPad のホーム画面アプリ体験向上)
- マルチユーザー (認証層は auth_tokens の拡張で対応可能な設計にしてある)
- 外部フォルダ参照 (External Library)。採用する場合は改名・削除追従の設計が必要
- Windows Hello 対応 (vault 生体認証)
