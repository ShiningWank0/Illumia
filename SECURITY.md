# Security Policy

## Supported versions

Until v1.0 is published, security fixes are provided on the current `main` branch only.
After v1.0, the latest v1.x release and `main` are supported. Older pre-v1 releases are
unsupported and may contain known vulnerabilities.

## Reporting a vulnerability

Do not disclose credentials, tokens, private image metadata, Vault identifiers, filenames,
proof-of-concept payloads, or other sensitive details in a public Issue.

Use GitHub's private vulnerability reporting flow:

1. Open this repository's **Security** tab.
2. Select **Advisories** → **Report a vulnerability**.
3. Include the affected version/commit, impact, reproduction steps, and a minimal proof of concept.

If private vulnerability reporting is unavailable, contact the repository owner through the
GitHub profile without including exploit details, and request a private reporting channel.

We aim to acknowledge a report within 7 days. Disclosure timing is coordinated after a fix and
release are available. Please avoid accessing data you do not own or degrading a live service.
